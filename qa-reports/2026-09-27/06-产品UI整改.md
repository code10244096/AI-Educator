# 产品 UI 整改（P0 / P1）

日期：2026-09-27  
范围：需求文件 `05-产品UI需求.md` 中 UI-01 到 UI-14 里标了 P0 / P1 的条目。P2（UI-15 到 UI-19）未做。文件末尾「明确未核实」的项没有改文案。

浏览器走的是已登录的本地页 `http://127.0.0.1:3000`（账号 123456）。没有点「生成教案」「开始批改」「重新生成」「生成变式题」，没有上传新作业，没有删除现有批改、学生或教案「导数的几何意义」。空表单点了取消，没有新建班级或学生。没有停掉 3000 和 8000。

现有后端是 `uvicorn main:app --host 127.0.0.1 --port 8000`，启动时没有 `--reload`。本轮改过的 `backend/routers/workbench.py` 没有进到这个进程里。下面凡是写「现网仍是旧统计」都是这个原因。

## UI-01　P0　待复核数字和名单

**改了什么**

工作台以前把 `review_status` 不是 `reviewed` 的已完成提交都算进「等你确认」，历史数据里这一列是空的，所以 473 份已批改全被算进去。作业页只把明确写成 `pending_review` 的算待复核，所以作业集 1 的筛选是 0 人。

现在三处用同一套规则：只有 `status=completed` 且 `review_status=pending_review` 才算「等你确认」。已经确认（`reviewed`）和历史空值都不算。展开名单不再在接口里只留 5 条；页面先显示 5 条，多出来的写「还有 N 次（M 人/份）」，并有「查看全部」。学生行状态：`pending_review` 显示「待你确认」并给出确认；`reviewed` 显示「已确认」；其余已批改显示「已批改」。待复核筛选下，统计卡改成「待你确认」人数，不再旁边还挂着「已批改 45」。

**改了哪些文件**

- `backend/routers/workbench.py`
- `backend/tests/test_workbench.py`（已完成且未标记 pending_review 的提交，`pending_review` 断言为 0；确认之后计数变为 0）
- `frontend/src/pages/Workbench.jsx`
- `frontend/src/pages/HomeworkDetail.jsx`
- `frontend/src/utils/api.js`（`markReviewed`）

**验证结论：未通过（现网进程没加载新统计）**

单测里这条规则是对的。浏览器上现网仍是旧接口：工作台卡片是「待复核 473 份」，最近作业里「高考数学作业集1」仍标「待复核 45」。作业页 `?filter=review` 是「待你确认 0」、平均分「-」、名单 0 人，文案是「没有符合条件的学生」。卡片、展开名单、作业页筛选在当前 8000 进程上还不是同一套数。「还有 N 次」要等接口返回完整名单后才会出现，这次展开仍会被旧接口截成 5 条。按约定没有重启后端。

## UI-03　P0　错题本和班级批改对不上

**改了什么**

查过库：班级批改几乎都没有 `grading_result`，错题表是空的。同步逻辑只在逐题结果里 `is_correct=false` 时写入错题本。张三作业集 1 只有分数和错题数，没有题目和知识点，接不上已有数据，没有伪造错题。

空状态改为：「这里还没有错题。班级作业里的错题请先到对应作业查看。」并链到「我的班级」。去掉「作业批改中的错题会自动收录」。上传按钮写明「上传错题文件（图片、PDF、Word、TXT、MD）」。知识点拆成两个控件：「上传时填写的知识点」（占位「例如：导数」）和「筛选知识点」。

**改了哪些文件**

- `frontend/src/pages/WrongNotebook.jsx`

**验证结论：通过（按接不上数据时的文案验收）**

错题本加载完后是上述空状态，有「我的班级」链接，没有旧的自动收录文案。上传说明和两个知识点控件分开。宽屏和约 390 宽都能看到完整占位「例如：导数」，没有横向撑出页面。

## UI-14　P1　最近作业的下一步

**改了什么**

每一行都有独立的下一步按钮，不再套在标题按钮里。规则：批改中 →「查看进度」；有未批改的上传 →「去批改」；有待你确认 →「去复核」；否则「查看」。摘要里固定写出已上传、未交、待批改、批改中、已批改，有完成份数时带均分。

**改了哪些文件**

- `frontend/src/pages/Workbench.jsx`

**验证结论：未通过（和 UI-01 同一原因）**

「解析几何专项」是 38 份待批改、0 份已批改，按钮是「去批改」，这一条对。已批改的作业集仍显示「去复核」，因为现网接口还把空的 `review_status` 算成待复核。新代码在 `pending_review` 为 0 时应显示「查看」。后端进程没重载，这一条在浏览器上还不能按新规则验收。
