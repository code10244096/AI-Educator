# AI 教学助手（教师版）产品需求文档 PRD

> 版本：v1.0（首个上线版本）　分支：`feat/ai-teaching-launch`　日期：2026-09-26　作者：产品经理（AI）
> 读者：产品负责人 / 开发 agent / 测试 agent

## 摘要

**总体结论：当前版本还不能交给老师使用，但离可用并不远。** 核心闭环“建班 → 布置作业 → 上传 → AI 批改 → 逐题正确率与做错名单 → 错题变式 → 教案”在后端基本打通。真实模型实测一份手机拍照作业（4 题）66.6 秒批完，识别和判定都正确，还发现了老师参考答案里的错误，AI 能力本身够用。阻碍上线的是“产品外壳”和“安全底座”：

1. **不安全**：登录是假的（密码 123456 即可），所有接口没有鉴权、没有按教师隔离；Docker 镜像会把模型密钥和数据库打进去。
2. **不可信**：识别不到题目时记成“0 分、已完成”并拉低班级平均分；老师不能改判 AI 的结果；学号不同的同名学生导入时会被丢掉。
3. **不好用**：45 人的作业只能逐个上传，每人来回跳转 3 次；桌面端导航默认隐藏；首页是没有入口的动画页；页面上到处是“dataset / 测试数据 / class4 / #14”。
4. **有假功能**：题库管理三个子页面全部是写死的假数据；设置页的“修改密码”没调接口却提示成功。
5. **部署会失败**：nginx 默认 1MB 上传限制会拦掉手机照片；没有备份；首包 JS 1.88MB（gzip 548KB）。

**需求规模**：共 31 条需求，**P0 11 条**、P1 12 条、P2 8 条。上线条件为第 2 章上线标准全部通过，且全部 P0、P1 验收通过。

**第 1 轮范围（全部 P0 + 2 条 P1，共 13 条）**：真实登录与账号开通（R1-001）、接口鉴权与按教师隔离（R1-002）、生产安全基线（R1-003）、下线假功能（R1-004）、清理演示数据与开发概念（R1-005）、常驻导航 + 工作台（R1-006）、作业内批量上传 + 批改队列（R1-007）、失败判定 + 逐题改判（R1-008）、部署与备份（R1-009）、首屏拆包（R1-010）、同名学生按学号区分（R1-011），以及公式统一 KaTeX 渲染（R1-012）、加载/空/错误三态与 404（R1-014）。第 2 轮完成其余 P1（复核页、移动端、错题本教师化、Excel 导出与导入、教案参数、可观测性、E2E 测试、视觉统一）后做上线评审。

**需要产品负责人确认的 13 个问题**见第 5 章，均已给出推荐默认方案（如：单校多教师、管理员开通账号；首版只做高中数学；题库先隐藏；按正确题数计分），开发不必等待回复。

## 1. 产品定位、目标用户与核心使用场景

### 1.1 产品定位

**给高中数学老师用的“AI 批改 + 学情”助手。** 老师把收上来的纸质作业拍照上传，AI 识别并逐题批改，老师花几分钟复核，就能拿到全班逐题正确率、做错名单和错题。围绕这个闭环，再提供错题变式和 AI 教案两个备课工具。

一句话价值：**把“改 45 本作业”从 2 小时压到 20 分钟，并且改完就知道该讲哪几道题。**

首个上线版本的边界：
- 做：高中数学；教师端（电脑为主、手机拍照上传为辅）；单校多教师；AI 批改结果老师可逐题复核、改判。
- 不做：学生端/家长端；其他学科；题库资源运营；排课、考勤、成绩发布等教务功能。

设计原则（给开发和测试的判断依据）：
1. **老师的时间最贵**：常用操作 3 次点击内可达；批量优先于逐个；后台跑的任务不能要求老师守着。
2. **AI 可以错，但老师必须能看见、能改**：每道题都能对照原图复核和改判，AI 的不确定要明说。
3. **页面上只出现老师的语言**：不出现 dataset、测试数据、slug、token、调试模式这类词；运维功能不进教师菜单。
4. **不做假功能**：没有接后端的按钮宁可不显示，也不能点了提示“成功”。

### 1.2 目标用户

| 角色 | 描述 | 首版支持方式 |
|---|---|---|
| 高中数学教师（主要用户） | 带 1~3 个班、每班 40~50 人；每周布置 3~5 次作业；在办公室电脑上处理为主，课间用手机拍照上传；对 AI 半信半疑，需要能核对 | 完整使用全部教师功能 |
| 学校管理员 / 运维（次要） | 学校信息老师或部署方，负责开通账号、看模型用量和费用、备份数据 | 命令行开通账号 + 仅管理员可见的用量页 |
| 学生 / 家长 | 不直接使用 | 无端口；作业由老师代为上传 |

### 1.3 老师一周的真实工作流（核心使用场景）

以“王老师，高一 5 班、6 班数学，每班 45 人”为例：

| 时间 | 老师在做什么 | 产品里的操作 | 对应模块 |
|---|---|---|---|
| 学期初（一次性） | 拿到教务给的学生名单 Excel | 新建班级 → 导入 Excel 名单（同名学生靠学号区分） | 班级 |
| 周一 · 备课 | 下周讲“函数的单调性”，需要一份新授课教案 | 教案 → 填课题/年级/课时/学情 → 后台生成约 1 分钟 → 编辑 → 导出 Word 交教研组 | 教案 |
| 周一 · 课后 | 布置课本练习 1~4 | 班级 → 布置作业 → 粘贴参考答案（每题一行） | 作业 |
| 周二 · 早读 | 课代表收齐作业本 | 用手机把每个学生的作业拍下来（1~3 页/人） | — |
| 周二 · 第一节课前 | 把 45 份作业交给 AI | 作业详情 → 批量上传 → 系统按文件名自动对应学生，老师修正几个没对上的 → 开始批改；然后去上课 | 批改 |
| 周二 · 课间 | 看看批完没有 | 手机打开工作台：“高一5班·单调性练习 已批 38/45，预计 6 分钟” | 工作台 |
| 周二 · 下午 | 复核 | 作业详情看全班分数 → 打开几份低分/AI 标记“需复核”的 → 对照原图改判 1~2 道题 → 标记已复核；识别失败的 2 份重拍重传 | 批改结果 |
| 周三 · 讲评课前 | 决定讲哪几题 | 作业详情看“逐题正确率”：第 3 题正确率 42%，做错名单 26 人 → 打开错题本该题 → 生成 3 道变式题 → 导出练习纸 | 学情 / 错题本 |
| 周五 | 周回顾、准备家长沟通 | 班级学情：各次作业平均分、需关注学生（低分/成绩骤降/未交）→ 导出成绩 Excel | 学情 |

这条链路里任何一环断掉（比如只能逐个上传、结果不能改、名单导不进来），老师就会退回手工批改。所以本 PRD 的 P0 都围绕“这一周能不能完整走下来、数据是不是安全可信”。

## 2. 上线标准（Definition of Launch-Ready）

**总规则**：下表每一条都必须由测试 agent 实际检验并记录结果（通过/不通过 + 证据）。全部条目通过，且第 4 章所有 P0、P1 需求验收通过（P1 如需豁免，须产品负责人在第 7 章书面确认），才可上线。

### 2.1 功能

| 编号 | 标准 | 检验方法 |
|---|---|---|
| L-F01 | 新教师从登录开始，能在不看文档的情况下走完：建班 → 导入名单 → 布置作业（含参考答案）→ 批量上传 ≥3 名学生作业 → 看到逐题结果 → 改判 1 题 → 看到逐题正确率与做错名单 → 错题生成变式题 → 生成并导出一份教案 | 测试 agent 在模拟模式按此脚本走一遍，全部步骤无报错、无死链；真实模型模式至少走通一次“上传→批改→结果” |
| L-F02 | 教师可见的每一个按钮、菜单、表单都有真实效果；不存在“点了只提示成功但没保存”的功能 | 逐页点击所有可交互元素，对照后端数据/网络请求确认 |
| L-F03 | 教师界面不出现开发/运维概念：`dataset`、测试数据、测试集、调试模式、slug（如 `class4`）、`#ID`、token、模型名 | 全站文本检索（`get_page_text`）+ 代码检索 |
| L-F04 | 识别失败、解析不到题目的批改显示为“失败/需处理”，不产生 0 分、不计入任何统计 | 上传空白图片/无关图片，检查结果状态与成绩档案 |
| L-F05 | 老师可以逐题改判，改判后分数、错题本、逐题正确率、成绩档案同步更新 | 改判一题后分别检查 4 处数据 |

### 2.2 体验

| 编号 | 标准 | 检验方法 |
|---|---|---|
| L-U01 | 桌面（≥1024px）侧边导航常驻可见；当前页面在导航中高亮；任一页面 ≤3 次点击可到达任一核心功能 | 1366×768 下逐页检查 |
| L-U02 | 登录后首页是“工作台”，能直接看到待办（待批改/批改中/需复核）并一键进入 | 登录后截图检查 |
| L-U03 | 每个列表/详情页都有且区分三种状态：加载中（骨架或 spinner，不显示“暂无数据”）、空状态（说明 + 下一步按钮）、错误（中文原因 + 重试按钮） | 断网/停后端、空账号、正常账号三种条件下逐页检查 |
| L-U04 | 375px 宽度下所有页面无整页横向滚动（`document.documentElement.scrollWidth <= 375`），顶栏不换行，按钮文字不竖排；表格在手机上改为卡片或在容器内横滑 | 手机视口逐页执行 JS 检查 + 截图 |
| L-U05 | 数学公式在批改结果、错题本、逐题分析、教案中统一用 KaTeX 渲染，不出现 `\frac`、`\(`、`\displaystyle`、字面量 `\n` | 用含分式/上下标/根号的真实批改结果检查 |
| L-U06 | 批改、教案在后台运行，页面显示阶段、已用时间和预计剩余；离开页面再回来进度不丢；完成后顶栏任务抽屉/工作台有提示。变式题生成（约 30 秒）期间显示进行中状态和预计时间，且不阻塞页面其他操作 | 批改、教案、变式题各测一次 |
| L-U07 | 所有破坏性操作（删除班级/学生/作业/批改记录/教案）有二次确认，并说明会连带删除什么 | 逐个触发检查文案 |
| L-U08 | 未知路由显示 404 页（含返回工作台按钮），不出现白屏 | 访问 `/no-such-page` |

### 2.4 安全

| 编号 | 标准 | 检验方法 |
|---|---|---|
| L-S01 | 真实账号登录：密码 bcrypt 哈希存储；登录失败提示不区分“账号不存在/密码错误”；同一账号 5 分钟内失败 10 次锁定 15 分钟 | 接口测试 + 查库 |
| L-S02 | 除 `/health`、`/api/auth/login` 外，所有 `/api/*` 未登录返回 401；前端遇 401 跳转登录页并在登录后回到原页面 | 不带凭证逐个请求接口（可用 FastAPI 路由表自动遍历） |
| L-S03 | 按教师隔离数据：教师 B 访问教师 A 的班级/学生/作业/批改记录/原始文件/错题/教案，一律返回 404（列表中也不可见） | 两个账号交叉请求全部资源接口的自动化测试 |
| L-S04 | 用量统计等运维接口与页面仅管理员可访问；教师访问返回 403，菜单中不出现 | 教师账号访问 `/usage`、`/api/usage/*` |
| L-S05 | 密钥不入库、不进镜像：大模型 key、JWT secret 只从环境变量/挂载的配置文件读取；存在 `.dockerignore`，镜像内无 `config.json`、`*.db`、`uploads/`、`venv/`、`api_runs/` | `docker run --rm <image> ls -la /app` 检查 |
| L-S06 | 生产环境关闭 `/docs`、`/redoc`、`/openapi.json`；`debug=false`；CORS 只允许部署域名；全站 HTTPS | curl 检查 |
| L-S07 | 上传安全：扩展名 + 文件头双重校验；单文件 ≤10MB、单份作业 ≤10 个文件（批量上传按学生拆成多个请求）；存储名随机；原始文件只能由所属教师下载 | 现有 `test_security.py` + 新增越权下载用例 |
| L-S08 | 生产启动不播种演示数据；首次启动数据库为空（只有管理员通过命令创建的账号） | 全新数据目录启动后查库 |

## 3. 现状评估

### 3.0 评估方法与完成度一览

### 3.3 作业批改（`/grader`）

实测记录：

### 3.10 题库管理（我的题库 / 真题资源库 / AI 智题库）

`QuestionBank.jsx` **没有调用任何后端接口**：
- 我的题库：5 道写死的题（2024-01），上传弹窗“确认上传”只是 `setTimeout` 2 秒后关闭，什么也没保存；查看/编辑/删除/筛选无响应。
- 真题资源库：10 个写死的卷子卡片，“查看”“下载”无响应。
- AI 智题库：不管输入什么，3 秒后都返回同样 3 道三角函数题；“采纳”无响应。
- 后端 `/questionbank/*` 接口存在，但 `question_bank` 表 0 行。

结论：上线前隐藏（R1-004），上线后重做（R1-030）。

### 4.2 P0 需求详情

#### R1-001 真实登录、退出、改密，管理员命令开通教师账号（P0｜前+后）

**用户故事**：作为老师，我用学校开通给我的账号登录，只看到自己的数据；离开办公室电脑时可以退出，别人打不开我的班级。

**方案要点**
- 后端新增 `routers/auth.py`：
  - `POST /api/auth/login`（`username`, `password`）→ 成功时设置 httpOnly、`SameSite=Lax`、生产 `Secure` 的会话 Cookie（JWT，默认 7 天，可配置），同时返回 `{id, username, display_name, school, role, must_change_password}`。
  - `POST /api/auth/logout`、`GET /api/auth/me`、`PUT /api/auth/me`（修改姓名、学校）、`POST /api/auth/change-password`（校验旧密码；新密码 ≥8 位且同时含字母和数字）。
  - 登录限流：同一账号 5 分钟内失败 10 次，锁定 15 分钟；失败提示统一为“账号或密码错误”。
- `users` 表补字段：`display_name`、`school`、`role`（`teacher`/`admin`）、`must_change_password`、`is_active`、`last_login_at`；密码用 bcrypt（`passlib` 已在依赖中）。
- 管理命令 `backend/manage.py`：`create-user --username --name [--role admin] [--school]`（交互输入或随机生成初始密码并打印一次，`must_change_password=true`）、`reset-password`、`disable-user`、`list-users`。
- 前端：
  - 登录页只保留产品名、一句话介绍、账号/密码表单，删除“演示密码 123456”“返回首页”；登录成功跳回 `redirect` 参数指向的页面，默认工作台。
  - 路由守卫：未登录访问任何业务页 → `/login?redirect=<原路径>`；axios 拦截 401 → 清空本地用户信息并跳登录页，提示“登录已过期，请重新登录”。
  - `must_change_password=true` 时，登录后只能看到“设置新密码”页。
  - 顶栏右侧：老师姓名 + 下拉菜单（个人资料 / 修改密码 / 退出登录）。

```
┌──────────────────────────────────────────┐
│              AI 教学助手                   │
│   拍照上传作业，AI 逐题批改，老师一键复核     │
│  ┌────────────────────────────────────┐  │
│  │ 账号  [ 手机号或工号               ] │  │
│  │ 密码  [ ••••••••               👁 ] │  │
│  │        [        登 录          ]    │  │
│  │  忘记密码？请联系学校管理员重置        │  │
│  └────────────────────────────────────┘  │
└──────────────────────────────────────────┘
```

**验收标准**
1. Given 管理员执行 `python manage.py create-user --username 13800000001 --name 王老师`，When 用打印出的初始密码登录，Then 先进入“设置新密码”页；设置后进入工作台，顶栏显示“王老师”。
2. Given 错误密码或不存在的账号，When 登录，Then 均提示“账号或密码错误”，接口返回 401。
3. Given 同一账号连续 10 次密码错误，When 第 11 次用正确密码登录，Then 提示“尝试次数过多，请 15 分钟后再试”（返回 429）。
4. Given 未登录，When 直接访问 `/class`，Then 跳到 `/login?redirect=%2Fclass`，登录后回到 `/class`。
5. Given 已登录，When 点击“退出登录”后按浏览器后退，Then 页面不显示任何业务数据，接口返回 401。
6. Given 会话有效期配置为 1 分钟，When 过期后点击任意按钮，Then 跳转登录页并提示“登录已过期，请重新登录”。
7. 数据库 `users.password_hash` 以 `$2b$` 开头；全站不再出现“123456”“演示账号”“演示密码”字样。
8. 修改密码：旧密码错误提示“当前密码不正确”；新密码不合规提示具体规则；成功后用新密码可登录、旧密码不可登录。

#### R1-002 所有接口鉴权，数据按教师隔离（P0｜后，前端配合 401 处理）

**用户故事**：作为老师，我班上学生的姓名、作业照片和成绩只有我能看到，其他老师登录后看不到也访问不到。

**方案要点**
- 除 `/health`、`/api/auth/login` 外，所有 `/api/*` 路由加 `current_user` 依赖（建议在 `api.py` 的 `APIRouter(dependencies=[...])` 统一挂载，避免遗漏）。
- 归属字段：`classes.teacher_id`、`homework_assignments.teacher_id`、`homework_submissions.teacher_id`（新增，覆盖不关联班级的临时批改）、`wrong_questions.user_id`、`lesson_plans.teacher_id`。去掉所有写死的 `user_id=1`。
- 所有查询按当前教师过滤；按 ID 访问不属于自己的资源一律返回 **404**（不用 403，避免泄露存在性）。包括：原始文件下载 `/grader/{id}/files/{i}`、班级子资源、批改任务、错题、教案导出、`/tasks/*`。
- 后台任务（批改、教案、错题同步）使用任务所属教师 ID，不依赖请求上下文。
- 迁移（幂等、无损）：`python manage.py assign-orphans --username <教师账号>` 把所有无归属的存量数据归到该教师；启动迁移只加列不删数据。
- 大模型调用日志增加 `teacher_id`。

**验收标准**
1. 自动化测试遍历 `app.routes`：未带凭证请求每个 `/api/*` 业务接口，全部返回 401（白名单除外）。
2. 自动化测试：教师 A 创建班级、学生、作业、提交（含文件）、错题、教案；教师 B 对上述每一个资源调用 GET/PUT/DELETE/子资源接口，全部 404；B 的所有列表接口（班级、作业、批改记录、错题、教案、任务）不包含 A 的任何数据。
3. 教师 B 直接请求 A 的原始作业文件 URL → 404。
4. 用当前 `teaching_assistant.db` 的副本执行迁移并 `assign-orphans` 到教师 A 后：A 能看到全部旧数据，新建的教师 C 看不到任何旧数据。
5. 前端：任一接口返回 401 时跳登录页（见 R1-001 第 6 条）。

#### R1-003 生产安全基线（P0｜后+运维）

**用户故事**：作为学校管理员，我需要确认部署后不会因为配置疏忽泄露密钥、学生数据或内部接口。

**方案要点**
- 配置外置：`LLM_API_KEY`、`JWT_SECRET`、`DATABASE_URL`、`CORS_ORIGINS`、`APP_ENV` 从环境变量（`.env`，不入库）读取；`APP_ENV=production` 时若 `JWT_SECRET` 缺失或仍为示例值，**拒绝启动**并打印明确原因。更新 `.env.example`，补齐 `config.production.json` 模板中缺失的 `llm` 段（或改为全部走环境变量）。
- 新增 `backend/.dockerignore`、`frontend/.dockerignore`（排除 `config.json`、`.env`、`*.db`、`uploads/`、`api_runs/`、`venv/`、`node_modules/`、`__pycache__/`、`tests/reports/`），并把根 `.gitignore` 中的 `.dockerignore` 规则删掉，使其入库。
- 生产：`debug=false`、关闭 `/docs` `/redoc` `/openapi.json`、SQLAlchemy 不打印 SQL、CORS 只允许部署域名；**生产禁止模拟模式**：`APP_ENV=production` 且没有有效 `LLM_API_KEY` 时拒绝启动（见 Q13）。
- 运维能力仅管理员：`/api/usage/*` 需 `role=admin`，教师 403；前端 `/usage` 路由对教师不可见、直接访问显示“无权限”；用量页不显示服务器绝对路径。
- 上传：在现有扩展名/大小校验基础上增加文件头（magic bytes）校验；单份作业 ≤10 个文件。
- 提交前检查：仓库内任何已跟踪文件不含明文密钥（`git grep` 检查 `sk-`、`api_key":"` 等模式）。

**验收标准**
1. `APP_ENV=production` 且未设置 `JWT_SECRET` 时后端启动失败，日志提示“生产环境必须设置 JWT_SECRET”；未设置有效 `LLM_API_KEY` 时同样启动失败。
2. 构建后的后端镜像中执行 `ls /app`，不存在 `config.json`、`*.db`、`uploads/` 中的旧文件、`venv/`、`api_runs/`。
3. 生产配置下 `GET /docs`、`/openapi.json` 返回 404；跨域请求来自非白名单 Origin 时无 CORS 放行头。
4. 教师账号访问 `/api/usage/summary` → 403；页面菜单中无“用量统计”；管理员账号可正常查看。
5. 把 `.exe` 改名为 `.jpg` 上传 → 400“文件内容与格式不符”；单份作业上传 11 个文件 → 400。
6. 现有 `tests/test_security.py` 全部通过。

- 作业详情页右上主按钮改为“上传作业”，打开批量上传面板（名录每行的“上传”也打开同一面板，并预选该学生，**不再跳转到 /grader**）：

#### R1-008 批改结果可信：失败判定、统一计分、逐题改判、复核状态（P0｜前+后）

**用户故事**：作为老师，AI 看不清或判错了我能马上发现并改正；改过的分数要同步到成绩和错题里，我才敢用这个成绩。

**方案要点**
- **失败判定**（后端 `jobs.py`）：以下情况一律 `status=failed`，不写分数、不同步错题、不计入任何统计：识别文本为空或少于 10 个有效字符；批改结果 JSON 解析失败；`total_questions == 0`；`questions` 为空。失败原因写老师能看懂的话，例如“未识别到题目，请检查照片是否清晰、是否拍到答题区域”“AI 服务暂时不可用，请稍后重试”。
- **计分口径统一**：`score = round(correct_count / total_questions × 100, 1)`，由后端根据逐题 `is_correct` 计算，不采用模型自报的分数（分值与步骤分见 P2 的 R1-031）。
- **逐题改判**：新增 `PATCH /api/grader/{submission_id}/questions/{question_number}`（`is_correct`、可选 `teacher_comment`）→ 后端重算 `correct_count/wrong_count/score`，并同步错题本（判错 → 新增错题；判对 → 移除该题的同步错题），记录 `teacher_modified=true` 与修改时间。
- **复核状态**：提交增加 `review_status`（`pending_review` / `reviewed`）。结果页有“标记为已复核”；作业详情名录可按“待复核”筛选。批改提示词要求模型逐题返回 `needs_review`（字迹不清、识别存疑、判定无把握时为 true）和 `reference_issue`（认为参考答案有误时说明原因）；有任一题 `needs_review` 的提交在名录中显示“建议复核”。
- 重新批改一份已被老师改判过的作业时，二次确认“重新批改会覆盖你的改判，确定吗？”。
- 迁移：库中已有的 `completed` 且 `total_questions == 0` 的记录改为 `failed`（原因“未识别到题目”），并从统计中剔除。
- 结果页上每题显示“判对 ✓ / 判错 ✗”切换按钮和批注输入框；页面顶部显示“AI 批改 · 老师已改判 1 题 · 待复核/已复核”。

**验收标准**
1. 上传空白图片（模拟模式用空 txt 或无题号文本）→ 该学生显示“失败：未识别到题目…”，成绩档案、平均分、逐题正确率、错题本均无变化。
2. 4 题对 2 题的作业得分为 50；把第 3 题改判为“对”→ 得分 75，错题本少 1 条，作业详情逐题正确率第 3 题更新，成绩档案该作业平均分更新，刷新后保持。
3. 把一道原判“对”的题改判为“错”→ 错题本新增该题，来源标注“老师改判”。
4. 对已改判的提交点“重新批改”→ 出现覆盖确认；确认后改判记录被清除。
5. 名录“待复核”筛选只显示 `review_status=pending_review` 的学生；点“标记为已复核”后从筛选中消失，工作台“待复核”数字减 1。
6. 模型返回 `reference_issue` 时，结果页显示黄色提示“AI 认为第 N 题参考答案可能有误：…”（用 fake AI 用例覆盖）。
7. 迁移后，原数据中“0 题 0 分”的记录显示为失败，不再拉低“高考数学作业集10”的平均分。

#### R1-009 部署可用：上传限制、compose 修正、数据卷、每日备份与恢复（P0｜运维）

**用户故事**：作为管理员，我在 2 核 2GB 的云服务器上一条命令部署，老师上传手机照片不会报错，服务器坏了数据也能找回来。

#### R1-011 学生以学号区分，同名学生不丢失（P0｜前+后）

#### R1-012 数学公式统一用 KaTeX 渲染（P1｜前｜第 1 轮）

**用户故事**：作为数学老师，我要看到正确排版的分式、上下标和根号，而不是 `\frac` 或 `(x2-x1)/(x1x2)` 这样的字符串。

3. 输入非法 LaTeX（如 `$\frac{1$`）时显示原文，控制台无未捕获异常。

#### R1-013 批改复核页：原图对照、上一份/下一份（P1｜前+后｜第 2 轮）

**用户故事**：作为老师，我复核时想左边看学生原图、右边看 AI 判定，看完一份直接点“下一份”。

**方案要点**
- 路由挂到作业下：`/class/:classId/homework/:assignmentId/review/:submissionId`；临时批改的结果用 `/grader/results/:submissionId`。旧的 `/tasks/sub-{id}` 重定向到新地址。
- 布局（≥1024px 左右分栏，手机上下排列）：


#### R1-014 加载/空/错误三态规范与 404 页（P1｜前｜第 1 轮）

**用户故事**：作为老师，我要能分清“正在加载”“确实没有数据”和“出错了”，出错时知道该怎么办。

**方案要点**

#### R1-020 可观测性（P1｜后｜第 2 轮）

**用户故事**：作为管理员，老师反馈“批改失败”时，我能凭一个编号在日志里找到原因。

**方案要点**
- 中间件：为每个请求生成 `X-Request-ID`（响应头返回），访问日志一行 JSON：时间、请求 ID、用户 ID、方法、路径、状态码、耗时 ms；写入 `logs/`，按天滚动。
- 未处理异常：记录堆栈 + 请求 ID；返回 `{"detail": "服务器开小差了，请稍后重试（编号 xxxx）"}`；前端错误提示展示该编号。
- `/health`：检查数据库可读写、上传目录可写、磁盘剩余 >1GB，失败返回 503 并列出失败项。
- 生产关闭 SQL echo；大模型调用日志增加 `teacher_id`，管理员用量页支持按教师、按天筛选。

**验收标准**：对应 L-O01 ~ L-O05 全部通过。
